## 4. Hallazgos (importancia ordenada)

1. **La migración a React no está desplegada.** `frontend-react/` está completa y con tests,
   y `npm run build` genera `frontend-dist/`, pero el backend sirve `frontend/` (la versión
   vanilla con rutas `#/…`). Ni `main.py` ni el `Dockerfile` recogen el build de React.
2. **La rama `react-migration` no dispara CI.** `.github/workflows/docker.yml` solo cubre
   `v2-desde-cero` y `main`; los 6 commits de la migración nunca han pasado por GitHub Actions.
3. **Falta la pantalla "Publica tu chamba" en React.** `src/api/client.js` ya expone
   `submitJob` y `jobSources`, pero ninguna página los usa; `/enviar` no existe en el router.
   Es la funcionalidad central del producto (scraping + envío comunitario).
4. **Docs desactualizados.** `README.md`, `docs/CONTRATO.md` y `docs/REPORTE_VERIFICACION.md`
   describen la versión vanilla (19 pantallas Stitch, E2E 64/64) y no mencionan la migración.
5. **Rutas que solo existen en vanilla**: `/libro-de-reclamaciones`, `/perfil-publico/:id`
   (en React solo llega `/legal/:tipo` para privacidad/términos/guias).

## 5. Conclusión

El backend y la web que está en línea son sólidos: 43 ofertas reales, 110 tests en verde y la
navegación verificada en móvil. El riesgo actual no es técnico sino de **coherencia**: hay dos
frontends (vanilla en producción, React terminado pero no servido) y la rama que se está
desarrollando no pasa por CI.Antes de exponer el proyecto conviene decidir cuál es el frontend
oficial y alinear la cadena (CI + despliegue + docs) con esa decisión.
